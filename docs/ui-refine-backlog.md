# UI refine: backlog and direction

Branch `feat/ui-refine`. Scope: `src/ui/` (the dashboard). Written 12 November 2026 from:

- the critique (28/40, C-01 to C-25) and the audit (15/20, A-01 to A-30, measured contrast, overflow and touch tables);
- `impeccable detect --json src/ui`, which returned `[]`;
- `DESIGN.md`, `PRODUCT.md`, and a check of the source for the inconsistencies neither evaluation listed.

File and line references are as of commit `0071bc8` and are relative to `src/ui/` unless a path says otherwise. They will move as phases land; search for the quoted class or string if a line no longer matches.

Note on `DESIGN.md`: the file on disk ends with "Do's and Don'ts", not with a list of inconsistencies. The inconsistencies below (button recipes, error treatments, notice recipes, text opacities, duplicated constants, off-scale sizes, rhythm, amber meanings, side stripes) were each confirmed in the source before being listed.

## Direction

**Chosen: the incumbent "quiet desk", made consistent, legible and usable at 390px.** Everything that identifies the app stays: the green-grey palette on warm paper, Seravek in three weights, the docked sidebar and drawer, flat surfaces with hairline borders, daisyUI and Tailwind, sentences in place of labels, and every route, behaviour and data shape. What changes is the finish. Three decisions carry most of it. (1) Text has two tones only: Ink, and one muted tone defined as a solid token that measures at least 4.5:1 on Desk Paper, Sidebar Sage and the open-row tint; the ten opacities in use today (45 to 85%) collapse into those two, which clears about 800 failing text nodes. (2) Colour meanings narrow to one each: amber means "waits for you" (count tiles, count badges, the waiting-for-approval dot, a notice about a held person); a spent budget becomes quiet (a full Dark Moss meter and the sentence saying when it resumes), as `PRODUCT.md` requires of a state that is not a problem; solid red is the safety stop, "LinkedIn needs you" and a destructive confirm, with other errors as red text only; the amber and red side stripes on the focused approval row and the activity lines go. (3) At 390px a table is a table only while its columns fit: the People and Stats tables become one stacked block per row below their breakpoint (the move Home and Campaigns already make), an opened person's texts wrap to the viewport, and controls grow to a 44px target below 1024px. Shared recipes come first (one secondary button, three error treatments, one notice, one status line, named sizes) so that later phases edit one place.

Alternatives rejected:

- **A bolder recolour** (new hues, tinted panels, stronger brand colour). The palette is committed and the user is non-technical and brief; both evaluations found the colour system sound and its rules merely broken in places. A recolour would break the identity rule of this run.
- **A card per row on the phone, everywhere.** The approval queue, Home and Campaigns already stack well; converting all tables would add height (the queue is already 7,618px for eight people) and a second layout to maintain. Only the two tables that fail get stacked.
- **Keep sideways scroll and add a fade cue only.** It leaves a sent message unreadable without dragging (914px of prose in a 356px box) and fails reflow for the prose panel.
- **Keep amber for a spent budget and darken it.** It keeps "full meter" and "waits for you" the same colour, the one confusion `PRODUCT.md` forbids in spirit; a neutral fill also fixes the 1.57:1 meter with no new hue.

### Guardrails for every phase

1. Refinement only. Keep identity, behaviour, routes, data and copy meaning. No new feature, page or flow (`AGENTS.md`: "No feature the spec does not name"). Only visual, layout, typography, colour, states, responsiveness, accessibility and motion.
2. UI text uses `CONTEXT.md` vocabulary. Change other copy only for a real clarity problem.
3. Anything that needs an engine or server change, a behaviour change or new navigation is deferred: move the row to the deferred table with the reason.
4. Never touch LinkedIn: no `npm start`, `npm run live:check` or `npm run linkedin:open`. Look at the app only through the seeded demo apps that Playwright starts (`playwright.config.ts`, fake driver).
5. `data-testid` attributes, roles and accessible names used by `e2e/dashboard.spec.ts`, `e2e/screens.spec.ts` and `e2e/screenshots.spec.ts` must keep working. If a visible label changes for vocabulary, update the tests in the same commit.
6. `npm run verify` passes before each commit.
7. Read `/Users/masterp/.claude/skills/impeccable/reference/craft-floor.md` before editing.
8. Phone width (390) is a supported layout. Check every change at 390 and 1440; no page may scroll sideways at 390.
9. When an item is done, set its Status to `fixed <sha>`; if it turns out to need a deferred change, set `deferred: <reason>`.
10. Stay on `feat/ui-refine`. Screenshots use test data only.

### Judgement calls to report to the user

- **Vocabulary renames (B-06).** "Working hours" becomes "Working window" and "Daily limits" becomes "Budgets". Authorised by the run's brief ("Use CONTEXT.md vocabulary in all UI text"); the critique's note that this needs the principal's yes is superseded.
- **"Limit reached, resumes tomorrow 09:00" becomes "Budget spent, resumes tomorrow 09:00" (B-06).** Same reasoning, but `PRODUCT.md` and `DESIGN.md` quote the old sentence and `e2e/dashboard.spec.ts:50` asserts it, so it is the most visible rename.
- **A spent budget is no longer amber (B-07).** `DESIGN.md`'s Amber Waits Rule currently covers it; this run narrows amber to "waits for you". `DESIGN.md` is updated in `polish`.
- **Lead paragraphs go from Ink 75% to full Ink (B-01).** The price of having two tones instead of ten.
- **C-02 ranked P2, not the critique's P1 (B-31).** The audit measured that the Stats table scrolls inside its box and is not clipped, and a data table is exempt from reflow.
- **Small label changes for clarity:** "Open" becomes "Open review" (B-13), the Home "Needs you" sentences are recased (B-43), "Download its people as CSV" becomes "Download as CSV" (B-44), and "(the claude command)" moves from the option label to the hint (B-32).
