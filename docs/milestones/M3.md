## How scoring works

1. **Discovery** loads LinkedIn's suggestions (My Network → Grow) or a people search page by page. It skips anyone who is already a connection, has a pending invitation, is marked do-not-contact, was contacted before, or is active in another campaign.
2. **Card score.** The AI scores up to ten cards per call against your scoring brief, 0–10 with a reason. Below the campaign's open-profile threshold the person is rejected without a profile view.
3. **Profile view**, counted against the daily profile-view limit, then a **profile score** with what the profile supports about industry and size.
4. **Name cleaning.** "Dott. Marco Rossi 🚀 | Growth" becomes "Marco". What the AI returns is checked against what LinkedIn showed: a first name must be a word of the full name, a short company name must be made of the company's own words, an industry needs a confidence of at least 0.7 and a source. Otherwise the field stays empty and the person is held for review when a message would need it.
5. At or above the score threshold the person waits in the **approval queue** with the score, the reason, the evidence, and the invite note, first message and follow-up as they would be sent to that person. Auto-approve is off by default and needs an explicit confirmation to start with.

The AI never decides whether something is sent. Scoring and name cleaning are not LinkedIn activity: they also run at night and during a safety stop, and load no page.

## Anthropic's terms for the `claude` CLI on a schedule

Checked on 2026-11-12 from Anthropic's own pages. In short: **permitted for one person's own use at this scale, by their documentation rather than by an explicit clause, so a small grey area remains.**

- The Consumer Terms forbid automated access "except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it".
- The Claude Code documentation supplies that permission for scripts: it describes a token for "CI pipelines, scripts, or other environments where interactive browser login isn't available" that "authenticates with your Claude subscription", and a support article (updated 2026-10-07) says `claude -p` "still draw[s] from your subscription limits".
- Limits: a five-hour session limit and a weekly limit shared with normal Claude use; advertised limits "assume ordinary, individual usage".
- Not allowed: offering Claude login inside an app for other users, or routing other people's requests through a subscription. One person running the unmodified `claude` binary on his own login is neither.
- Uncertain: "ordinary, individual usage" is not defined and no page names scheduled jobs; the documentation says a mode that does not use the subscription login "will become the default for `-p` in a future release".

This matters for Alex more than for you: his install would run on his own subscription under the same terms. The fallback is the Anthropic API key, which the terms exempt outright; that provider is built but was tested only against a mocked connection, because no key exists on this laptop and I was told to create none.
